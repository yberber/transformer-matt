# One Python core; the Trace is both the Example file format and the API contract

The offline regeneration script and the live inference server call the same Python package to tokenize, run GPT-2 and build Traces, and an Example file is the same shape as a live API response: header plus position records, plus `first_position`. A Step response from token IDs holds only the new Positions, and `first_position` says where that slice starts, since a position record's attention row is only as long as its Position. With Prompt text, `first_position` is 0, and the response minus that field is exactly an Example file. We chose this over separate pipelines so that "Live mode returns the same tokens and probabilities as Example mode" and "visualizations behave the same in both modes" hold by construction, and the frontend has a single decoding path. The cost is that the Example file format cannot evolve independently of the API: any change to one is a contract change for both, guarded by the committed schema.
